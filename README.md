# Violations Watch

Source for **https://violationswatch.org**: an open log of reported violations of international humanitarian law (IHL) and international human rights law (IHRL), shared as leads for investigators, journalists and researchers.

Most entries are **unverified leads, not findings**. Each one records what was reported, by whom and when, with links to the original sources and archived copies where available.

## What's here

| File | What it is |
|---|---|
| `index.html` | The site: map, filterable incident log, method and corrections |
| `data.json` | The incident data the page loads (incidents last reported in the past 28 days) |
| `incidents.csv` | The same data as CSV (UTF-8 with BOM, one row per incident) |
| `archive.html` | The permanent archive of older incidents |
| `archive.json`, `archive.csv` | Every archived incident (incidents move here 28 days after they were last reported) |
| `feed.xml`, `feeds/` | RSS feeds: all new incidents, grave violations against children, and one per country |
| `sources.json`, `sources.js` | Source types (news agency, state media, rights group, social media…) by domain, shown next to each original report |
| `mechanisms.html` | Where to take evidence: accountability mechanisms |
| `legal.js`, `legal_types.json`, `legal_contexts.json`, `treaty.js`, `treaty_status.json` | The "what the law says" and treaty status panels |
| `blog/` | The blog (posts in `blog/posts/`) |
| `world.json`, `world-50m.json` | Country outlines for the map (Natural Earth via world-atlas, public domain) |

| `_headers`, `_redirects` | Security and caching headers, and redirects, for the static files |
| `wrangler.jsonc` | Cloudflare Workers settings and the build command |

### Incident pages

Every incident has its own page at `/i/VW-YYYY-NNNN/`, rendered on request by `src/worker.js` from the deployed data files, so the daily data commit updates them too and no page files need to be built or stored. These pages are open to search engines and listed in `/sitemap-incidents.xml` (also generated by the Worker). Withdrawn incidents return a "not in the log" page that search engines are told not to index. Only `/i/*` and `/sitemap-incidents.xml` run the Worker; every other request is served straight from the files.

### Built on each deploy (not committed)

- `blog/posts.json` and `sitemap.xml`, by `scripts/build-blog.js`
- `archive-data/`: the archive split into one file per year of VW number, by `scripts/build-archive.mjs`, so the archive page and incident pages load one year at a time. `archive.json` stays the complete download.
- `og/`: a link-preview image for each incident in the current log, plus `og/index.json`, by `scripts/build-previews.mjs`

### Source types

`sources.json` maps domains to a type of outlet. A subdomain takes its parent's type, and a domain not listed shows as "Unclassified". To label a new outlet, add its domain under `domains` with one of the keys under `types`. The label describes the outlet, not the accuracy of a report.

## How the data is updated

The data files are regenerated from the project's incident register every morning (the refresh starts at 05:40 UK time and the site is updated by about 06:30) and committed here, so the commit history is a public, dated record of every change. Incidents keep a permanent ID (`VW-YYYY-NNNN`); corrections update the entry rather than removing it silently.

## Citing

Cite incidents by their VW number and the date you accessed the site, for example: *Violations Watch, VW-2026-0041, accessed 14 Nov 2026, https://violationswatch.org/i/VW-2026-0041/*. Each incident's page keeps working after it moves to the archive.

## Blog

The blog lives in `blog/` and is live at https://violationswatch.org/blog/.

### Writing a post

1. Copy `blog/posts/_template.md` to a new file named `YYYY-MM-DD-short-title.md` in `blog/posts/`, e.g. `2026-12-01-sudan-hospitals.md`.
2. Fill in the front matter (title, date, summary, author, tags) and write the post in Markdown below it.
3. Commit. Cloudflare rebuilds the post list (`blog/posts.json`) automatically on every deploy.

Mention an incident number such as `VW-2026-0041` and it becomes a link to that incident. Put images in `blog/images/`.

`draft: true` hides a post from the public list (it can be previewed at `/blog/?drafts`). **This repository is public, so anything committed, drafts included, can be read on GitHub.** Write drafts elsewhere and commit only when ready to publish.
